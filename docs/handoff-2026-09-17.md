## 2. 上游路由模型（本 session 主体，已实现 P1–P4）

**设计文档：`docs/design/upstream-routing-model.md`**（含决策台账 D1–D7、数据模型、P5 余项）——接手先读它。要点速览：

- 用户可见概念收敛为两个：**上游资源**（持有模型映射表）+ **访问密钥**（持有有序上游集合，顺序=优先级）。转换按端点自动推导（零配置），can-serve 未命中让位下一位。
- GatewayBinding 保留为**内部派生层**：`core/upstreamRouting.ts` 的 `deriveKeyUpstreamBindings`/`assembleGatewayBindings` 把新模型数据投影成旧绑定，解析引擎/dispatcher/模型列表/路由锁定全部原样复用。
- 存储：密钥行 `upstreamBinding`（`'all'` 活引用 / explicit 有序列表，空=403，缺省=未迁移走 legacy）+ server 配置 `upstreamModelMappings`（按 `providerId` / `sub:<providerId>` 键控）+ `defaultKeyUpstreamBinding`（新密钥默认，'all'|'none'）。
- admin 面：`GET /admin/api/upstreams`（目录+映射+liveBindings 派生聚合）、`PUT /admin/api/upstreams/:key/mappings`（多行无 `*` 拒绝）、`POST /admin/api/keys/:id/upstream-binding`、`POST /admin/api/upstreams/migrate-legacy`（幂等，`upstreamMigrationDone` 闸门）、`POST /admin/api/upstreams/rollback-legacy`。
- 变更重派生触发点：密钥/映射/Provider/accounts 变更 + 启动（`commands/start.ts`）。`reapplyLiveServerConfig` 保持 running 状态不变。

**实现中固化的三个语义**（易踩）：
1. 路由器对带 `upstreamBinding` 的密钥**只认 `keyup:<id>:*` 派生绑定**（否则 legacy all-scope 兜底会让 403 失效）；launch preflight 同规则（`bindingsServingKey`）。
2. **空订阅池不进目录**（零账号 pool 在 passthrough can-serve 下黑洞任意模型名——实测打到过真 Anthropic）。
3. gemini 角色键（`default`/`background`）与名字行并存时**角色键优先**，名字行只喂后台检测。

测试入口：`packages/core/src/outbound-api/__tests__/upstreamRouting.test.ts`（7）、`packages/daemon/src/__tests__/admin-upstream-routing.test.ts`（8，e2e 含 403/派生服务/映射解析/迁移回退）。

**P5 余项（刻意未做，绑定回退窗口）**：legacy `server.bindings` 读取路径、`dispatchMode:'prefix'`、`boundUpstream` 直连层的删除——待迁移稳定一个版本后一并清。「下游与路由」页签已隐藏（深链仍可达，`upstreamTab:'routes'`）。

## 4. 安装器杀进程（e630a98）

`apps/desktop/src-tauri/nsis-installer.nsh`（`tauri.conf.json` → `bundle.windows.nsis.installerHooks` 接线）：
- **隐形首页**（hooks 文件在模板页声明前被 include，Page 顺序最前）在重装页执行旧卸载器**之前**杀进程——官方 PREINSTALL 钩子在 Section 里，晚于该步骤救不了。带旧安装注册表守卫（全新安装不提前杀）。
- PREINSTALL（覆盖静默安装）+ PREUNINSTALL（本版自己的卸载器）。
- 杀法严格路径限定：`Get-Process | Where-Object Path -Like '$INSTDIR*' | Stop-Process -Force`（比较语句语法无 `$_`，NSIS 不会误读 `$`）；**绝不按映像名杀**（历史事故：杀掉别人家的 node）。
- 验证到：PS 单行真机杀 2 个 node + 目录可删；makensis 编译零错；完整 `build:app` 产出含 hooks 的 setup.exe。**用户实机升级路径未确认跑通**——若再报「无法安装」，先查这里。
- 注意：`TAURI_SIGNING_PRIVATE_KEY` 未设时 `build:app` 尾部 updater 签名步骤失败（预期，不影响 setup.exe）。

## 5. 教训与陷阱（下一个 session 必读）

1. **`cn()` 无 tailwind-merge**（`packages/ui/src/shared/utils/utils.ts`）：同元素冲突 class 靠 CSS 顺序定胜负；生成样式表里 `max-w-2xl/4xl/6xl` 排在 `max-w-lg` **前**，所以比 lg 宽的弹窗覆盖必须 `!` 前缀（`!max-w-6xl`）。ChatGptWebPage 是先例，add-provider/AddAccountDialog/ConflictDialog 已修（1ae563c）。新弹窗想超 lg 宽度记得 `!`。
2. **i18n 三语 parity 测试**（`staticKeyResolution.test.ts`）：en 新增键必须同步 zh + zh-Hant，否则测试红。其余 30+ 语言回退 en。
3. **daemon typecheck 走 core 的 dist**：core 改完必须 `npm run build -w @omnicross/core` 再 typecheck daemon；子进程测试（route-lease-terminal-lifecycle）也解析 dist。
4. **NSIS hooks 文件必须纯 ASCII**（makensis 按 ACP 读）。
5. **UI 改动要重建 `packages/ui/dist`**（`npm run build -w @omnicross/ui`）daemon 才能伺服到；桌面应用则要 `npm run build:app`（**在仓库根跑**，不是 apps/desktop）。
6. 测试噪音：`headerBuilderVersion`（全树扫描）与 image e2e 在并行负载下超时是已知抖动，单跑即过，勿当回归。
7. **Node v24/undici 的 abort-after-headers 不再断线**：SDK 的 AbortController 只让本地 body 迭代器抛错，undici 会继续把响应**排空**以复用连接——服务端完全看不到断开。要测服务端取消语义，客户端必须 `socket.resetAndDestroy()`（RST）；`destroy()`/FIN 是半关闭，服务端照常写完（image-daemon-openai-sdk 的 cancellation 用例即栽在这上面，已改 RST）。
