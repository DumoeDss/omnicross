# 密钥查看密码

在「设置 → 安全」设置 Omnicross 自己的查看密码（8–128 个字符），不依赖 Windows PIN 或 Windows Hello。默认关闭；设置后每次查看或复制已保存的供应商 API key、客户端访问密钥，以及导出凭证迁移包时，都要单独输入密码。修改或关闭保护需要当前密码。正常模型请求、输入或替换密钥不受影响。

前端只临时保留通过验证取得的明文，不写入 provider 列表缓存或浏览器存储。切换供应商、切换 API 模式、关闭显示、离开页面、窗口失焦或超过 30 秒后清除显示。A → B → A 切换、等待验证时编辑和窗口失焦都会使旧请求失效。复制已显示的旧密钥也会重新验证，包括输入框的原生复制操作。

忘记密码可选择「清除凭证并重设」，并勾选删除确认。此操作永久清除供应商主密钥、密钥池、API 模式与套餐密钥、订阅登录凭证、客户端访问密钥、自定义请求头、搜索凭证、代理密码及 Webhook／计费密钥。客户端访问密钥会被撤销，历史记录保留。配置与模型映射保留；之后需要重新填写凭证。操作不修改外部 CLI 的原生登录文件、系统环境变量，也不删除此前已经导出的迁移包。搜索运行时的部分配置需要重启 daemon 才完全更新。

后端在 `${configPath}.key-viewing.json` 保存随机盐和 scrypt 校验值，不保存明文查看密码。连续 5 次错误会进入持久化的 60 秒冷却。校验记录损坏或不可读时拒绝访问，不降级为未保护状态。认证和对应的读取、密码修改、恢复操作串行处理；恢复完成清理后才安装新密码，失败保留原校验值。恢复期间也会等待正在进行的订阅刷新，防止旧凭证写回。

查看密码是应用内的显示和导出保护；拥有本机文件、进程或开发调试权限的人仍可访问应用运行所需的凭证。原有的静态凭证加密机制继续使用原来的主密钥。

## 管理 API

所有端点继续受原有 admin 认证约束。密码只接受 JSON 请求体，不接受 URL 参数，不发放可复用的解锁会话。敏感响应设置 `Cache-Control: no-store`。

| 操作 | 请求 |
| --- | --- |
| 查询是否开启 | `GET /admin/api/key-viewing-password` → `{ enabled }` |
| 设置／修改 | `PUT /admin/api/key-viewing-password`，`{ currentPassword?, newPassword }` |
| 关闭 | 同上，`newPassword: null` |
| 忘记密码恢复 | `POST /admin/api/key-viewing-password/reset`，`{ newPassword, confirmClearCredentials: true }` |
| 读取供应商主密钥 | `POST /admin/api/providers/:id/reveal-key`，`{ viewingPassword? }` |
| 读取客户端密钥 | `POST /admin/api/keys/:id/reveal`，`{ viewingPassword? }` |
| 导出迁移包 | `POST /admin/api/export`，`{ passphrase, viewingPassword? }` |

旧的 GET reveal 接口仅在保护关闭时可用。保护开启后，未验证请求返回 403，冷却期间返回 429，校验存储不可用返回 503。新增／修改供应商和普通列表接口保持只返回脱敏信息。恢复使用临时文件和原子替换写入配置与校验记录，避免写入失败截断原文件；跨文件恢复失败可能已清除部分凭证，但不会解除仍存凭证的原密码保护。

回归测试使用临时目录和虚构凭证，覆盖服务端逐次验证、导出绕过、持久冷却、校验损坏、恢复失败、热更新清理，以及前端切换竞态、复制、超时和失焦。禁止用真实用户凭证测试恢复删除。
